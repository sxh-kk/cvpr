# XMovePick 5000步失败定位与RTC动作有效通道修订

原始测评固定保存：30例中13例原生成功，RTC test_time，15个30Hz动作对应25个
50Hz控制步；每例总预算800步，包含50步真实预热。原始权重、场景与视频不覆盖。

## 已确认的边界

30例均实际运行RTC。初始化共记录30×201个200Hz物理子步，机器人与目标接触为零，
目标最大位移约1.048毫米。额外代表场景CPU广义接触检查未发现原初始化机器人与桌面、
干扰物或自身的正力接触。因此目标在策略阶段被推落，不能归为预热已经碰倒。

17例失败均跑满800步。6例目标几乎未动，10例目标移动后落低，1例很晚才形成明显交互；
目标最大抬升不超过约24.1毫米，尚未达到原生约90毫米成功阈值。
旧记录没有逐策略物理子步的手部/碰撞信息，不能据此指定首次碰撞的部件。

训练与原生预热后的肘、肩姿态存在分布差异；L2中9/10目标X位置超出训练99条的
初始目标X范围。二者是需另行验证的候选因素。仅添加DEFAULT冷启动会引入手指-髋部
自身接触，故本修订不采用该候选，不移动目标、机器人或桌面，不插入教师初态。

## RTC有效动作通道

已验收打包协议为body64加手指14，共78个监督通道，末2维是无监督padding。
原RTC按80维计算残差、VJP与纠偏幅度。新增显式
`--rtc-guidance-action-scope validated_repack`，仅在部署READY、run config、
PACK_READY、packer来源及精确repack协议通过绑定后，屏蔽后2维的RTC目标残差。
采样初始高斯噪声、80维输出、训练损失、模型参数、反归一化、15动作执行窗口均不变。
跨维Jacobian仍可改变全部输入通道，以满足有效通道约束；不将padding输入噪声置零。

默认 `all` 保留旧行为，以便同场景、同种子单因素对照。`validated_repack`
在本入口须显式诊断模式和test_time RTC，不允许静默改变原30例成绩。
服务/info、startup及逐请求真实sampler参数都记录认证proof与实际mask。
归一化previous/shifted prior/prediction及实际反归一化输出也留下只读诊断记录。
这项协议修正本身不等于已证实成功率提升，改善须由实际GPU对照确认。

## 显式小样本对照

`evaluate_pick30.py --diagnostic-cases 0:6,0:0,2:7,0:4` 冻结完整30例来源，
仅执行明确选择的4例，使用独立诊断合同及4例分母，不宣称完整30例成绩。
分别覆盖原失败的无交互、落低、晚交互，以及一例成功对照；采样种子仍为
`20261105 + 10*level + case_index`。先比较原all与validated_repack，
权重/初始化/物理/历史/RTC参数和执行窗口一致。`--rtc-mode off --execute-steps 15`
也可用于后续开关对照，保持同一0.5秒重规划周期，避免混入off默认30动作的差异。

开启 `--pick-interaction-diagnostics` 后，每例原生reset1步及每控制步4个真实物理子步
都由只读观察器计数；查询已解算contact force，不调用额外mj_forward或物理步。
记录机器人-目标/桌面/干扰物/自身和目标-桌面/干扰物接触，明确每个力属于前一解算区间。
每控制步同时记录实际送入控制器的body64/具名手指目标、实际43关节及腕/根/目标位置。
完成时校验实际1+4×控制步数、真实时钟终点、动作和接触证据，缺失即技术失败。
真实MuJoCo测试已验证观察与不观察轨迹逐字节相同。

全部实验使用独立输出目录、真实退出码、视频和双端HTTP/RTC验收；不自动重试、
不延长任务预算、不修改成功阈值，不用已选小样本冒充完整成功率。

## 2026-11-12 实际结果

同5000步权重的有效通道RTC四例为0/4，原all80对应1/4，因此不提升为默认。
RTC关闭但保持15动作执行窗口的完整30例为18/30（60%），L0/L1/L2均6/10；
原RTC为13/30。11例改善、6例退步，净增5例。所有30例技术有效，真实601次普通
采样、0次RTC，原场景/初始化/seed逐例一致，exit0且owned清理通过。该单轮差异不证明
稳定解决失败；相同种子和状态的重复测试已观察到微小渲染差异及成功翻转，
尚未隔离这些图像差异对翻转的单独因果作用。

同四例10000步RTC关闭仅2/4，与5000步RTC关闭2/4持平且成功场景不同，不据此更换权重。
mode0→mode1加固定上肢准备姿态的5000步RTC开启试测为4/4，原对应1/4；此候选修改预热参考。
正常控制还使root相对原预热前移约16.9mm并转向约2.29°，不能只将收益归于上肢。
它保留原生scene和全部任务预算，明确不是原始官方初始化，详见
[准备姿态实测](README_xmove_ready_upper.md)。完整ready30已在既有GPU队列真实全退出后
单独运行，于北京时间05:03:08完成21/30（70%），三组各7/10，比原13/30多成功8例；
全部技术有效、490次实际RTC、0初始化机器人碰目标、30份视频及真实清理退出齐全。
它保留5000步权重与原场景种子，修改预热且明确非原初始化成绩；仍有9例失败，
单轮诊断不等于独立heldout benchmark或稳定解决所有失败。

实际结果根目录`/var/tmp/cvpr-xmove-failure-fix-20261111/`保存各独立final、
PAIRED_RESULT与EXIT证明；原13/30结果未改写。
